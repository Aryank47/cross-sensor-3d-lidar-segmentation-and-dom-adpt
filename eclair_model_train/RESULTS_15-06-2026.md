## 11. Baseline Harmonization Control: C1-E ECLAIR Alpha and Rare-Aware Sampling

The source-only baseline evaluation showed a substantial ECLAIR→DALES common-space domain gap. The ECLAIR-trained source model achieved **0.8535 mIoU** and **0.9157 Macro-F1** on ECLAIR common-space evaluation, but dropped to **0.6272 mIoU** and **0.7212 Macro-F1** on DALES. This corresponds to an absolute mIoU gap of **0.2263** and a relative mIoU drop of **26.5%**.

Before moving to domain-generalization methods, I ran one additional baseline-control experiment, called **C1-E**, to test whether part of the ECLAIR→DALES gap could be explained by insufficient class balancing in the ECLAIR source baseline.

### 11.1 Hypothesis

The hypothesis behind C1-E was:

> Some part of the ECLAIR→DALES transfer gap may come from ECLAIR source training being under-balanced for rare utility-relevant classes, rather than from domain shift alone.

This was a reasonable control to test because the cross-domain failures were concentrated in sparse and utility-relevant classes such as poles, fence, and vehicles. In the baseline ECLAIR→DALES result, several of these classes showed low recall on the DALES target set. Therefore, the question was whether increasing the training pressure on ECLAIR rare classes would improve the model’s ability to detect similar rare classes in DALES.

C1-E was not designed as a domain-generalization method. It was a source-only baseline harmonization control. The model was still trained only on ECLAIR labels, without DALES labels or DALES unlabeled data. The training label space also remained the native ECLAIR 11-class label space. The common 7-class label space was used only for final same-domain and cross-domain reporting.

### 11.2 Method

C1-E modified the clean ECLAIR source training recipe in two ways:

1. **Per-class focal-loss alpha weighting**
2. **Rare-aware weighted tile sampling**

The model architecture, feature contract, and label-space protocol were otherwise kept consistent with the source-only baseline. The input features remained returns-only:

- `return_number` one-hot features
- `number_of_returns` one-hot features
- no intensity
- no RGB
- no coordinate features

The purpose was to test class-balancing pressure, not to change the input modality or the evaluation protocol.

#### 11.2.1 Per-class alpha weighting

The focal loss can be written as:

\[
L_{\text{focal}} = -\alpha_t(1-p_t)^\gamma \log(p_t)
\]

where:

- \(p_t\) is the predicted probability for the true class,
- \(\gamma\) controls how strongly the loss focuses on hard examples,
- \(\alpha_t\) is the class-specific weight for the true class.

In C1-E, larger alpha values were assigned to rare ECLAIR utility classes. This does not change the cached points or the labels. Instead, alpha changes the loss contribution during training. After the model predicts logits for a training batch, the loss contribution from each labeled point/voxel is scaled by the alpha value of its ground-truth class. Therefore, rare classes receive stronger gradient contribution during backpropagation.

In simple terms:

\[
\text{larger } \alpha_t
\Rightarrow
\text{larger loss for class } t
\Rightarrow
\text{larger gradient contribution during backpropagation}
\]

So alpha is an optimization-side mechanism. It is applied during loss computation and backpropagation, not during cache construction.

#### 11.2.2 Rare-aware weighted tile sampling

The second change was rare-aware weighted tile sampling. This mechanism acts before the forward pass.

Instead of sampling every ECLAIR training tile uniformly, the sampler increases the probability of selecting tiles that contain rare classes such as wires, poles, towers, fence, and vehicles. Conceptually, if tile \(i\) has sampling weight \(w_i\), then the probability of sampling that tile is:

\[
P(i) = \frac{w_i}{\sum_j w_j}
\]

Tiles containing more rare-class evidence receive larger weights. This changes how often a tile appears during training, but it does not modify the cached point cloud. The cache still stores the same points and labels. The sampler only changes the training exposure frequency.

Thus, C1-E applies class balancing at two levels:

| Mechanism | Stage | What it changes |
|---|---|---|
| Rare-aware tile sampling | Data loading | Which ECLAIR tiles are seen more often during training |
| Alpha weighting | Loss/backpropagation | How much each class contributes to the gradient |

Validation and evaluation were not sampled or reweighted. They used the normal test split and the same pointwise evaluation pipeline as the baseline report.

### 11.3 Results

The C1-E checkpoint was evaluated in three required views:

1. ECLAIR→ECLAIR native/train-space evaluation
2. ECLAIR→ECLAIR common-space evaluation
3. ECLAIR→DALES common-space evaluation

The results are:

| Evaluation | Label space | mIoU | Macro-F1 |
|---|---|---:|---:|
| C1-E → ECLAIR | native 11-class | 0.6768 | 0.7505 |
| C1-E → ECLAIR | common 7-class | 0.7188 | 0.7937 |
| C1-E → DALES | common 7-class | 0.6359 | 0.7312 |

Compared with the original ECLAIR source baseline:

| Metric | Original ECLAIR baseline | C1-E | Change |
|---|---:|---:|---:|
| ECLAIR→ECLAIR common mIoU | 0.8535 | 0.7188 | -0.1347 |
| ECLAIR→ECLAIR common Macro-F1 | 0.9157 | 0.7937 | -0.1220 |
| ECLAIR→DALES common mIoU | 0.6272 | 0.6359 | +0.0087 |
| ECLAIR→DALES common Macro-F1 | 0.7212 | 0.7312 | +0.0100 |

C1-E slightly improved cross-domain transfer from ECLAIR to DALES:

\[
0.6359 - 0.6272 = +0.0087
\]

However, this improvement came with a much larger drop in same-domain ECLAIR common-space performance:

\[
0.7188 - 0.8535 = -0.1347
\]

Therefore, C1-E does not represent a successful improvement over the source-only baseline.

### 11.4 Domain-gap calculation

For consistency with the baseline report, the domain gap is computed as:

\[
\text{Gap}_{S \rightarrow T}
=
mIoU^{common}_{S \rightarrow S}
-
mIoU^{common}_{S \rightarrow T}
\]

and the relative drop is:

\[
\text{Relative Drop}_{S \rightarrow T}
=
\frac{
mIoU^{common}_{S \rightarrow S}
-
mIoU^{common}_{S \rightarrow T}
}{
mIoU^{common}_{S \rightarrow S}
}
\times 100
\]

For C1-E:

\[
\text{Gap}_{ECLAIR \rightarrow DALES}
=
0.7188 - 0.6359
=
0.0829
\]

\[
\text{Relative Drop}
=
\frac{0.0829}{0.7188}
\times 100
=
11.5\%
\]

Although this relative drop is smaller than the original baseline relative drop of **26.5%**, this should not be interpreted as a domain-generalization improvement. The reduction is mainly caused by the collapse of the same-domain ECLAIR anchor, not by a large improvement on DALES.

A useful method should reduce the gap by improving target-domain transfer while keeping the source-domain anchor stable. C1-E does not satisfy that condition.

### 11.5 Per-class interpretation

The ECLAIR same-domain common-space result shows that C1-E overcorrected toward rare classes.

| Common class | IoU | Precision | Recall | Interpretation |
|---|---:|---:|---:|---|
| ground | 0.9602 | 0.9790 | 0.9804 | Stable |
| vegetation | 0.9636 | 0.9865 | 0.9766 | Stable |
| buildings | 0.4444 | 0.4621 | 0.9206 | Strong overprediction |
| wires | 0.9902 | 0.9941 | 0.9960 | Strong |
| poles | 0.7575 | 0.8159 | 0.9136 | High recall, some overprediction |
| fence | 0.1433 | 0.1474 | 0.8369 | Severe overprediction |
| vehicle | 0.7726 | 0.9703 | 0.7913 | Reasonable |

The most severe failure is fence. In ECLAIR common-space evaluation, the model predicted **55,015** fence points, while the true support was only **9,690** points. This produced high recall but very low precision:

\[
\text{Fence precision} = 0.1474
\]

\[
\text{Fence recall} = 0.8369
\]

This means the model became much more aggressive in predicting fence, but most of those predictions were false positives. Buildings show a similar, although less extreme, pattern: high recall but low precision.

On the DALES target set, C1-E slightly improves the overall mIoU, but the main target-domain bottlenecks remain:

| Common class | IoU | Precision | Recall | Interpretation |
|---|---:|---:|---:|---|
| poles | 0.3176 | 0.8759 | 0.3326 | Low recall remains |
| fence | 0.4296 | 0.5803 | 0.6233 | Moderate transfer |
| vehicle | 0.1652 | 0.9322 | 0.1672 | Very low recall remains |

The vehicle result is especially important. Precision is high, but recall remains very low. This means the model is still missing most DALES vehicles rather than simply confusing them with other classes.

### 11.6 Discussion

C1-E shows that the ECLAIR→DALES domain gap is not explained simply by ECLAIR rare-class underweighting. Increasing rare-class optimization pressure does produce a small target-domain gain, but it also makes the source-domain model substantially worse.

The result suggests that rare-class balancing is too blunt as a solution. It improves recall for some classes, but it also increases false positives, especially for fence and buildings. Therefore, the remaining domain gap is more likely related to source-specific context and scene-composition differences than to class imbalance alone.

This finding is useful because it rules out a simple explanation: the ECLAIR source model is not merely weak because it lacks rare-class weighting. A stronger class-balancing recipe alone does not produce a reliable cross-domain improvement.

### 11.7 Conclusion from C1-E

C1-E is not adopted as the new ECLAIR source baseline.

The original clean ECLAIR source checkpoint remains the main source-only baseline for the next domain-generalization experiments. C1-E is retained as a negative baseline-control result.

The main conclusion is:

> ECLAIR-side alpha weighting and rare-aware tile sampling slightly improve ECLAIR→DALES transfer, but they substantially degrade ECLAIR same-domain performance through rare-class overprediction. Therefore, simple rare-class balancing is insufficient to solve the observed domain gap.

This motivates moving to source-only domain-generalization methods that directly target scene/context dependence, such as source composition randomization and BEV auxiliary layout supervision.
